🌐 Set Static IP with nmcli (Ubuntu)

✔️ Step 1: Find your connection name & interface

List active connections:

bash
nmcli connection show --active

This will output something like:

pgsql
NAME           UUID                                  TYPE  DEVICE
Wired connection 1   xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx  ethernet  enp3s0

Suppose your Wi-Fi connection name is MyWiFi and interface is wlan0.

✔️ Step 2: Set a static IPv4 address

Basic format:

bash
sudo nmcli connection modify "<CONNECTION_NAME>" ipv4.addresses "<IP>/<PREFIX>" ipv4.gateway "<GATEWAY>" ipv4.method manual

Example (static IP: 192.168.1.50):

bash
sudo nmcli connection modify "MyWiFi" \
  ipv4.addresses "192.168.1.50/24" \
  ipv4.gateway "192.168.1.1" \
  ipv4.method manual

Example:

bash
sudo nmcli connection modify "MyWiFi" ipv4.dns "8.8.8.8 1.1.1.1"

To add multiple DNS servers, separate them with spaces.

✔️ Step 4: Bring the connection down & up

bash
sudo nmcli connection down "MyWiFi"
sudo nmcli connection up "MyWiFi"

This applies the new static IP configuration.

✔️ Step 5: Verify

bash
nmcli device show wlan0 | grep IP4

Or:

bash
ip addr show wlan0

To assign:

  • IP: 192.168.1.50

  • Netmask: 255.255.255.0 (prefix = /24)

  • Gateway: 192.168.1.1

What is /etc/resolv.conf
ChatGPT said:

/etc/resolv.conf is one of the most important network configuration files in Linux.
It controls DNS (Domain Name System) resolution — i.e., how your system converts domain names (like google.com) into IP addresses.

📌 What /etc/resolv.conf Does

It tells your Linux system which DNS servers to use.

A typical /etc/resolv.conf looks like:

nginx
nameserver 8.8.8.8
nameserver 1.1.1.1
search localdomain

  • nameserver → IP address of a DNS server

  • search → default domain appended to queries (optional)

📌 Who manages /etc/resolv.conf?

This depends on your Linux distribution and network manager.

On Ubuntu (modern versions):

/etc/resolv.conf is usually a symlink to a file managed by systemd-resolved:

swift
/etc/resolv.conf -> /run/systemd/resolve/stub-resolv.conf

or

swift
/etc/resolv.conf -> /run/systemd/resolve/resolv.conf

This means you should not edit it manually, because it will be overwritten.

📌 Where to configure DNS properly instead?

If you use NetworkManager (Ubuntu default):

Use nmcli or the GUI:

bash
nmcli connection modify "your-connection" ipv4.dns "8.8.8.8 1.1.1.1"
nmcli connection modify "your-connection" ipv4.ignore-auto-dns yes

Then restart:

bash
nmcli connection up "your-connection"

If using systemd-resolved directly:

Edit:

bash
/etc/systemd/resolved.conf

and configure:

ini
[Resolve]
DNS=8.8.8.8 1.1.1.1
FallbackDNS=9.9.9.9

Then restart:

bash
sudo systemctl restart systemd-resolved

📌 Why you should NOT edit /etc/resolv.conf manually?

Because:

  • NetworkManager will overwrite it

  • DHCP will overwrite it

  • systemd-resolved will overwrite it

  • Your changes won’t persist

Only systems without NM/systemd-resolved (minimal servers) should manually edit it.

📌 What systems edit this file manually?

  • Minimal Debian/Ubuntu servers without NetworkManager

  • Alpine Linux

  • Some container environments (Docker)

  • BusyBox-based systems

Editable manually? Usually no on Ubuntu
Managed by systemd-resolved, NetworkManager

Ubuntu’s DNS resolution system has changed over the years, but on modern Ubuntu (18.04 → 24.04) the internal flow is:

🔎 How Ubuntu Resolves DNS Internally

Ubuntu uses a layered approach involving:

  1. glibc resolver (your applications)

  2. systemd-resolved (DNS resolver service)

  3. NetworkManager (manages network and DNS settings)

  4. /etc/resolv.conf (stub file pointing to systemd-resolved)

  5. Actual DNS servers (like 8.8.8.8)

Let’s break this down step-by-step.

1️⃣ An application makes a DNS query

When you run:

bash
ping google.com

your program uses glibc’s resolver library.
glibc looks at:

  • /etc/nsswitch.conf → determines DNS is used

  • /etc/resolv.conf → finds DNS configuration

2️⃣ /etc/resolv.conf points to systemd-resolved

On modern Ubuntu, /etc/resolv.conf is not a real file.
It’s a symlink:

swift
/etc/resolv.conf → /run/systemd/resolve/stub-resolv.conf

This file typically contains:

nginx
nameserver 127.0.0.53

This means:

👉 DNS queries are sent to systemd-resolved, running on localhost (127.0.0.53).

3️⃣ systemd-resolved handles DNS queries

systemd-resolved is a DNS resolver + cache.

It:

  • Receives DNS queries

  • Checks its cache

  • Decides which DNS server to use:

    • From NetworkManager

    • From DHCP

    • From manual configuration

    • Per-interface DNS

  • Sends queries to external DNS servers

systemd-resolved also supports:

  • DNSSEC validation

  • Split-DNS (VPN + local domains)

  • Link-specific DNS settings

Check its status:

bash
systemd-resolve --status

4️⃣ NetworkManager sets DNS servers for systemd-resolved

NetworkManager controls interface DNS settings.

It gets DNS info from:

  • DHCP

  • Static configuration (nmcli connection modify)

  • VPN configurations

NetworkManager then hands DNS info to systemd-resolved via D-Bus.

This is why:

👉 Editing /etc/resolv.conf manually does nothing
👉 You should configure DNS through nmcli or NetworkManager

5️⃣ External DNS servers are queried

systemd-resolved sends DNS queries to the upstream servers you configured:

Examples:

  • 8.8.8.8 (Google)

  • 1.1.1.1 (Cloudflare)

  • DHCP-provided DNS (local router)

  • VPN DNS servers

systemd-resolved caches responses for faster lookups.

📌 Internal DNS resolution flow (summary)

pgsql
Application → glibc → /etc/resolv.conf → systemd-resolved
→ picks DNS server → external DNS → response cached → returned

🛠️ How to check actual DNS server being used

Check resolved’s DNS for each interface:

bash
systemd-resolve --status

Check the global stub DNS:

bash
cat /run/systemd/resolve/resolv.conf

Check what /etc/resolv.conf is pointing to:

bash
ls -l /etc/resolv.conf

You should see a symlink.

🧠 Key Takeaways

  • Ubuntu uses systemd-resolved as the DNS resolver.

  • /etc/resolv.conf is a symlink to a stub file, pointing to 127.0.0.53.

  • NetworkManager controls DNS configuration.

  • systemd-resolved supports caching, DNSSEC, split DNS, and more.

  • You should configure DNS using nmcli or NetworkManager GUI, not by editing resolv.conf.
